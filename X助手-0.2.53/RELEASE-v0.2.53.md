# v0.2.53：关注优先与统一节奏

正常通用API版本。只调整“列表关注加评论”；保留旧提示词、其他功能、去重和发送校验，完整旧版v0.2.52目录、ZIP及Git标签继续保留。

## 节奏与效率

- 目标平均40～60秒成功关注一人，以两次成功关注间随机40～50秒为节奏基准；关注前另保留1～3秒停顿和结果确认。
- 筛选名单、页面加载、评论和失败候选耗时自动抵扣关注间隔，已耗时足够就不再补等。无效账号不等待完整关注间隔，直接切换备用账号。
- 普通跳转前1.5～3秒，换来源或刷新首页前4～7秒。到达后检测文档、主栏和当前阶段关键元素，不能只凭固定延迟直接操作。
- 首页和认证关注者列表最多12秒等待首批内容；资料最多15秒；目标帖子最多5秒。空列表有明确提示时直接切换来源；加载异常检查X网络，断网保留断点。
- 候选足够时提前结束多屏扫描，扫描最多20秒，保留备用候选；直接进入队列下一人，不重复绕回来源列表。

## 关注优先与期限

- 每个候选账号总预算90秒，包含导航、主页校验、关注节奏等待、关注和可选评论。跨主页、评论页和重载保存，状态心跳不续期。首页、列表阶段仍各最多60秒。
- 已关注账号或不符合原有中文资料、600～10000粉丝条件的账号直接跳过；每来源最多成功关注5人，不要求凑满。
- 关注先执行并确认，评论可放弃。关注确认后最多5秒找一条24小时内未处理原创帖，仅生成一次，不换帖、不重试。
- 评论从打开目标帖子前起总共最多40秒，且受账号剩余90秒预算限制；剩余不足12秒时不再开始找帖/打开帖子。
- 模型实际请求最多25秒，同时扣除8秒发送确认预留时间。时间不足、空内容、安全拒绝、格式不合格或发送失败直接结束可选评论。
- 停止任务、超时、恢复代次变化后，实际模型fetch取消，旧结果不能继续发送；已有生成尝试、pending、done、发送尝试或不确定记录均不重发。
- 页面每秒检查期限，后台约每30秒兜底。90秒是正常处理退出目标；系统休眠、浏览器调度和网络探测可能推迟实际跳转，恢复执行后先拦截过期操作。

## 故障恢复与显示

- X断网保存剩余阶段、账号和评论预算，每约30秒探测网络；恢复后继续，不重新获得完整90秒。
- 明确关注限速后的冷却、确认断网后的等待不当作普通卡死；不缩短平台限速冷却。模型连续故障3次仅暂停评论5分钟，继续关注。
- 控制台显示本次/今日关注和评论数、实际平均关注耗时、当前账号90秒用时、关注确认状态、评论剩余时间和超时计数。断网时账号、评论倒计时显示已保存的剩余时间；平均耗时包含筛选和等待。

## 验证与使用

执行 node --test tests/*.test.cjs：112项通过。其中本版46项测试运行实际策略、任务、恢复和模型脚本，覆盖节奏抵扣、页面就绪、90秒总期限、40秒评论期限、发送预留、停止、断网恢复和防重发。10账号虚拟时钟模拟中，包含换来源、15秒多屏扫描、页面加载、不同模型耗时和发送确认，平均48.05秒/成功关注。此结果是模拟验证，未进行真实关注、评论或付费请求，实际均速受网络、平台和合格候选数量影响。
