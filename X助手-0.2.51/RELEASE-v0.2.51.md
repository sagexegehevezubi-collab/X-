# v0.2.51：列表关注加评论卡死修复与网络恢复

本版为正常版本，保留通用 API 配置。v0.2.50 完整目录、ZIP 和 Git 标签继续保留，可独立恢复。

## 修复原因

旧版评论的异常处理在外层 catch 中调用了 try 块内部声明的 handleCommentFailure。评论超时或发送异常时，实际触发 ReferenceError，主循环退出，finally 又清除了页面看门狗，而控制台仍保留旧的“正在评论”状态。本版把失败处理器移到 catch 能访问的作用域，并为最外层启动调用增加异常兜底。

提供的自检记录中，心跳比自检时间早约 44 分钟，而即时模型生成和回复框探测成功。这支持“循环已经退出、状态未更新”的诊断，不能据此确定当时最初发生的是网络、模型还是页面异常。

## 网络异常与自动恢复

- 扩展后台用 chrome.alarms 每约 30 秒检查运行中的列表任务；无需依赖 X 页面上的计时器。网络错误页没有内容脚本时也能恢复原任务标签页。
- X 无法连接时暂停操作，保存来源、候选、已关注数量、帖子和尝试次数，不把断网直接当成一批博主失败。
- 模型连接异常会检查 API 地址可达性；408、429、5xx 进入等待和退避。API 密钥或参数错误不伪装成全网断开。
- 探测为有 8 秒超时的不带密钥 GET，不调用模型生成，也不发送评论。401/403/404/405 只代表服务可达，并不保证密钥、模型或实际 POST 请求可用；恢复后由真实生成请求继续判断。
- 连通后重新打开同一个任务标签页，按断点继续。断网等待期间暂停评论截止时间；发送已尝试但结果不确定的同一帖子仍不重发。
- 点击停止、切换任务或开始新任务后，旧回调不能恢复旧任务。关闭任务标签页后不会擅自新建替代页；主动转去其他网站的标签页不被抢占。

## 超时与防重发

- 单位博主评论链路累计 90 秒上限，覆盖帖子加载、生成、定位回复框和发送确认。普通首次失败仍等待 20 秒再试，第二次失败跳过；达到 90 秒则放弃当前博主，不再尝试该博主的备用帖子。
- 截止时间保存在断点中，刷新页面不会重新获得 90 秒。超时后禁止继续发送，再检查网络，正常网络下跳过；确认连接异常则转入等待恢复。
- 后台发现评论过期或循环失去进度时可独立推进断点。后台警报通常每 30 秒触发，浏览器或电脑完全休眠时不能保证准时执行，唤醒后再检查。
- 发送前检查任务、账号、恢复代次、候选和截止时间；旧模型结果、旧页面流程、超时后才就绪的编辑器均不能继续发送。
- 继续保留原有 replyAttempt、pending、done 和 uncertainReplyPostIds 去重记录。不能确认是否已经发送的帖子按不重发处理，避免断网恢复时双发。
- 网络恢复后账号导航尚未渲染，不会用空账号清空断点；登录账号与任务账号不同则停止并保留断点。
- 控制台同步显示定位回复框、写入、等待发送确认和网络等待状态；自检新增版本、网络恢复状态、评论截止时间和恢复代次。

## 更新与验证

更新正在使用的扩展时，先停止任务并备份原插件目录，再将本版文件复制到原插件目录，保持原路径，在浏览器扩展管理页点击“重新加载”，刷新 X 和控制台。这样可保留该扩展原有的浏览器本地配置和记录。也可将本目录作为新的未打包扩展加载，但不同扩展身份可能需要重新配置。

新增 alarms 权限用于后台恢复；如浏览器提示确认新权限，请在扩展管理页处理。旧的页面脚本会通过控制器版本检查要求刷新。

验证命令：`node --test tests/follower-target-recovery-v251.test.cjs`（仓库根目录运行）。22 项测试加载 v0.2.51 的实际任务和后台代码，用模拟网络、页面、时钟与存储覆盖异常、断网、后台重启、停止、旧回调、防重发等路径。全部脚本另做语法检查。没有执行真实关注、评论或付费模型测试，仍需在实际 X 页面观察运行结果。
