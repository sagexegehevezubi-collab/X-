# v0.2.52：列表关注加评论效率优化

正常通用 API 版本。此次流程调整仅用于“列表关注加评论”，保留其他任务和既有回复硬校验。旧版 v0.2.51 的完整目录、ZIP、Git 标签及提示词继续保留，可独立恢复。

## 关注优先的流程

- 认证关注者列表先多屏浏览、合并中文候选，扫描预算20秒；最少扫描3轮，足够时提前结束，除5位主候选外保留备用。最后一轮刚加载的账号也会收集。
- 严格逐个进入候选主页，检查关注状态及600～10000粉丝范围；已经关注的直接跳过，主页资料最多等15秒。
- 确认关注成功后才增加关注数。关注间隔仍至少20秒，每个来源最多成功关注5人，可少于5人；原有中文、关键词筛选保留。
- 关注后最多找帖5秒，仅选择一条24小时内、有文字、可回复、未处理的原创帖。没有合适帖子直接处理下一人。
- 每位只生成一次，不降级重试、不换第二帖。模型跳过、格式不合格或请求失败时放弃可选评论，继续关注。
- 队列内直接进入下一个候选主页，避免每处理一人都返回来源列表；用完候选后再补充列表或寻找新来源。
- 普通跳转停留2～4秒，返回首页3～6秒；列表按渲染变化提前结束等待。

## 时间上限与中断

- 评论全流程最多40秒：为保守控制，在打开目标帖之前就开始计时，包含导航、帖子加载、模型生成、定位回复框、写入、发送及结果确认，不按步骤各给40秒。
- 模型请求最多25秒，为发送确认留出余量；回复框最多等6秒，其他控件等待受评论剩余总预算约束。
- 普通任务阶段最多60秒，超时推进候选或来源；更新状态、心跳、重新加载同一阶段均不能重置截止时间。
- 截止时取消实际模型fetch，拦截迟到结果及旧流程继续关注或发送。停止、切换任务、恢复代次改变时也会取消模型请求。
- 单帖生成尝试及发送去重持久化。页面重新加载不会再次生成已开始处理的同帖；pending、done、replyAttempt及结果不确定的帖子均不重发。
- 页面每秒检查期限，后台约每30秒兜底。浏览器节流、系统休眠时不能保证准点跳转；恢复执行后先检查截止时间，过期流程禁止继续发送。
- X明确触发关注限速后的冷却、确认断网后的等待属于有意暂停，不计作普通页面卡死；本版不缩短既有平台限速冷却。

## 网络与模型故障

- X连接异常时保存断点并等待，每约30秒检查；网络恢复后重新打开原任务页继续。只做不带密钥、8秒超时的X连通性探测，不靠探测请求判断模型可用。
- 模型故障不会阻塞关注流程。连续3次接口故障后，仅暂停可选评论5分钟，期间仍逐个关注；到期后由后续真实请求判断服务是否恢复。
- 单次生成模式也不做协议/字段兼容的第二次请求；需要这些自动回退的网关应配置为直接兼容Chat Completions的地址。其他模块保留原有兼容回退和重试。
- 网络恢复保留剩余阶段预算，评论预算不超过40秒；已开始生成或已有发送尝试的帖子不重发。

## 统计、更新与验证

控制台新增本次成功关注、成功评论、放弃评论、评论超时、阶段超时、平均每关注耗时和当前阶段用时；API评论冷却及X断网等待单独显示。平均耗时包含等待，不能据模拟测试保证实际关注速度。

更新前先停止任务，将本版文件复制到原扩展加载目录以保持扩展身份和本地记录，再在Chrome/Edge扩展管理页点击“重新加载”，刷新X与控制台。也可重新加载本版目录，但新扩展身份可能需要重新设置接口。旧页面控制器版本检查会要求刷新。

在仓库根目录运行：node --test tests/*.test.cjs。新增测试执行本版实际脚本，模拟网络、时钟、存储和页面，覆盖单次生成、40秒全流程、25秒fetch取消、60秒阶段期限、直接切换候选、备用扫描、断网恢复、停止和防重发。另检查全部JS语法、扩展引用文件及ZIP逐文件哈希。没有执行真实关注、评论或付费模型请求，实际效率仍需在X页面观察。
